Features

Everything Rudo.ai runs, in detail

Four layers: a scanning engine, an AI analysis layer, reporting & tracking, and the deployment model underneath all of it.

Scanning Engine

Ten tools, one orchestrator

Each tool keeps doing exactly what it's good at. Rudo.ai's job is sequencing them against a target and normalizing what comes back.

Nmap

Port and service discovery — the first pass against any target.

Nuclei

Template-driven scanning for known CVEs and misconfigurations, kept current via regular template updates.

Httpx

Probes discovered hosts for live HTTP services and captures response metadata.

Subfinder

Passive subdomain enumeration to map the target's real attack surface.

Katana

Crawls web applications to surface endpoints, parameters and hidden routes.

SQLMap

Automated testing for SQL injection across discovered parameters.

FFUF

Fast content discovery for hidden paths, files and directories.

Dalfox

Focused XSS (Cross-Site Scripting) detection.

Arjun

Finds hidden HTTP parameters that other tools miss.

WhatWeb

Fingerprints the technologies powering each discovered web asset.

AI Layer

Analysis that adapts to how you want to run it

Universal AI Adapter

Three ways to run the model behind Rudo.ai's analysis: a managed cloud provider (Groq) for speed, bring-your-own-key through OpenRouter for flexibility, or Ollama for a fully local, offline-capable model when nothing should leave the network. Switch per deployment, not per feature.

Ask Rudo.ai

A conversational assistant scoped to the current scan's actual results. It explains what a finding means, what the realistic impact is, and what to fix first — in plain language, for whoever has to act on the report, not just whoever ran the scan.

Attack Chain Analysis

Individual findings rarely tell the full story. Rudo.ai links related results — an exposed endpoint, a weak auth header, a sensitive path — into the attack paths they could form together, so triage isn't just a flat severity-sorted list.

Data Masking

Before anything reaches a cloud AI provider, IP addresses and email addresses are stripped from the payload. It's one layer of a larger data-handling policy, not a complete privacy guarantee on its own.

Reporting & Tracking

Assessment is a process, not a one-off scan

Scan-Diff

Compare any two scans of the same target. See what's newly introduced, what's still open from last time, and what's actually been fixed — turning assessment into a trackable process instead of an isolated event.

PDF Reporting

Every scan can export a structured report — suitable to hand to a client or an internal stakeholder who isn't going to read raw tool output.

Deployment & Security

Runs on your infrastructure, by default

Self-Hosted via Docker Compose

No multi-tenant SaaS. Rudo.ai's components — the React frontend, the ASP.NET Core API, the Python tool-orchestration service, the database and the scanning tools themselves — run as containers on a server you control.

SSRF Protection

Scans against internal targets and localhost addresses are rejected by default — a specific control, not a substitute for securing the host server itself.
