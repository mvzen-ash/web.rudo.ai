Get Rudo.ai running locally

This covers the self-hosted Docker Compose build. Desktop-app docs will land here once downloads open.

System Requirements Installation Configure Secrets Connect an AI Provider Run Your First Scan Troubleshooting

System Requirements

  • Docker & Docker Compose (Docker Desktop on Windows/macOS, or Docker Engine on Linux)
  • 4 GB RAM minimum, 8 GB recommended — more if you run AI models locally via Ollama
  • A target you're explicitly authorized to scan. Rudo.ai rejects internal/localhost targets by default.

Installation

Clone the repository and copy the example environment file:

git clone https://github.com/mvzen-ash/rudo.ai.git
cd rudo.ai
cp .env.example .env

Start the full stack:

# macOS / Linux
./scripts/run_platform.sh

# Windows
scripts\run_platform.bat

This brings up the React frontend, the ASP.NET Core API, the internal Python tool-orchestration service, and PostgreSQL, all behind nginx. Once containers are healthy, open http://localhost.

First boot pulls and builds several containers, including the one running the ten scanning tools the orchestration service drives — the first docker compose up can take a few minutes.

Configure Secrets

Two values in .env need to be set before first boot — they aren't safe defaults, they're placeholders:

POSTGRES_PASSWORD=change-me-to-something-random
Jwt__Key=change-me-to-a-long-random-string
The double underscore in Jwt__Key isn't a typo — ASP.NET Core maps Section__Key environment variables onto nested configuration (here, Jwt:Key). Leave it out and the API fails its startup configuration check instead of booting with an insecure default.
PostgreSQL only applies the password in .env the first time its data volume is created. If you change it after the first boot, wipe the volume with docker compose down -v and start again — otherwise the API container will fail to authenticate against the database.

Connect an AI Provider

AI provider setup happens entirely in the app — no further .env edits needed. Open Settings after logging in and choose one:

  • Cloud — a managed provider (Groq) using your own API key.
  • Custom (BYOK) — any OpenAI-compatible endpoint, e.g. OpenRouter, with your key, base URL and model name.
  • Local (Ollama) — point at an Ollama instance running on your machine or network. Nothing leaves your infrastructure.
Running Ollama on the host while Rudo.ai runs in Docker? Start Ollama with OLLAMA_HOST=0.0.0.0 ollama serve — by default Ollama only binds to 127.0.0.1, which a container reaching it via host.docker.internal can't connect to.

Run Your First Scan

  1. Log in and create an account from the Rudo.ai UI.
  2. Add a target you're authorized to test, under Targets.
  3. Start a scan — the Orchestrator sequences all applicable tools automatically.
  4. Watch results populate in real time, then open Ask Rudo.ai to ask about any finding.
  5. Export a PDF report, or compare against a previous scan with Scan-Diff.

Troubleshooting

White page at http://localhost? Check docker compose logs nginx and docker compose logs api for the actual error — most often this is the API container exiting on startup because of the Jwt__Key or Postgres-password issues above.

npipe connection error on Windows? Docker Desktop isn't running. Start it, confirm with docker info, and make sure it's set to Linux containers.

Still stuck? Open an issue on GitHub.
